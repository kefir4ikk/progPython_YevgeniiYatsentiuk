## Модель продуктивності

Пікова продуктивність (одинарна точність, FP32):

```
P [MFLOPS] = f [ГГц] * 1000 * IPC * L
L = 1            для CPUKernel (скалярне ядро)
L = W / 32       для SIMDKernel (W = 128, 256 або 512 біт)
```

## Ієрархія класів

| Клас | Приватні атрибути | Властивості | Dunder-методи |
|---|---|---|---|
| `CPUKernel` | `__kernel_id`, `__clock_frequency_ghz`, `__ipc`, `__load_history` | `kernel_id` (лише читання), `clock_frequency_ghz`, `ipc` з валідацією, `performance_mflops`, `average_load_percent` | `__init__`, `__str__`, `__repr__`, `__eq__`, `__lt__`, `__add__`, `__radd__`, `__len__`, `__getitem__` |
| `SIMDKernel(CPUKernel)` | `__simd_width_bits` | `simd_width_bits` з валідацією, `vector_lanes`, перевизначена `performance_mflops` | перевизначені `__str__`, `__repr__`, `__eq__` |

## Семантика операторів

- `a + b` - нове зведене ядро: тактова частота дорівнює більшій із двох, ефективний IPC підібрано так, щоб `P(a + b) = P(a) + P(b)`; буфери телеметрії об'єднуються; операнди не змінюються. Працює і для різнотипних ядер (`CPUKernel + SIMDKernel`), а `sum([...])` працює через `__radd__`;
- `a < b` - порівняння за тактовою частотою (не за продуктивністю), тому `sorted()`, `min()`, `max()` працюють без додаткових методів;
- `a == b` - рівність класу, ідентифікатора, частоти та IPC (для `SIMDKernel` ще й розрядності); історія навантаження в порівнянні не бере участі;
- `len(core)` та `core[i]` (включно зі зрізами й ітерацією) - доступ до буфера телеметрії навантаження.

## Результат

Тестовий стенд виконує 7 груп перевірок і 23 автоматичні перевірки інваріантів, усі проходять (код завершення 0). Приклад: `core_a` (3,2 ГГц, IPC 2,5) = 8000 MFLOPS, `simd_a` (3,0 ГГц, IPC 2,0, 256 біт) = 48000 MFLOPS, `core_a + simd_a` = 56000 MFLOPS. Сортування за частотою ставить на перше місце `SIMD-1` (2,4 ГГц), який водночас має найбільшу продуктивність (57600 MFLOPS), тобто порядок за частотою не збігається з порядком за продуктивністю.
