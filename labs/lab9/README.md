### Мета: Опанувати практичні навички проектування стійких до відмов програмних комплексів мовою Python. Навчитися реалізовувати багаторівневу обробку помилок часу виконання за допомогою конструкції try-except-else-finally, проектувати ієрархію користувацьких класів винятків (Custom Exceptions) для конкретної інженерної предметної області, застосовувати механізм явної генерації винятків raise та зв'язування первинного контексту помилок через ланцюжки винятків (exception chaining). Опанувати парадигму EAFP (Easier to Ask for Forgiveness than Permission) для валідації параметрів апаратних пристроїв та конфігураційних файлів комп'ютерних систем.

## Ієрархія винятків

```
BaseException
└── Exception
    └── ADCValidationError            # базовий доменний клас (error_code, timestamp)
        ├── SamplingRateError         # rate_mhz, min_mhz, max_mhz              (ADC-ERR-2001)
        ├── InputOverloadError        # voltage_v, min_v, max_v                 (ADC-ERR-2002)
        └── NyquistViolationError     # signal_freq_mhz, sampling_rate_mhz,
                                      # nyquist_limit_mhz                       (ADC-ERR-2003)
```

Сам `ADCValidationError` використовується напряму для нечислових параметрів (коди 2004 та 2005).

## Що реалізовано

- валідація за парадигмою EAFP у чотири рівні: структура, типи, фізичні межі, інваріант Найквіста;
- ланцюжки винятків `raise ... from ...`: первинний `ValueError` зберігається в `__cause__` кожного доменного винятку;
- тестовий стенд із `try-except-else-finally`: `except` розташовано від найспеціалізованіших до найзагальніших, `else` фіксує успіх, `finally` виконується в усіх випадках;
- розрахунок `P_recovery = N_handled / N_total_faults` та лічильники за типами винятків.

## Результат

З 11 тестових наборів 2 коректні, 9 викликали нештатні ситуації. Локалізовано й оброблено 8; один збій (`TimeoutError` шини датчика) валідатор не передбачає, тому він потрапляє до фінального `except Exception` без визначеної дії відновлення. Коефіцієнт програмного відновлення `P_recovery = 8 / 9 = 88,89 %`.
