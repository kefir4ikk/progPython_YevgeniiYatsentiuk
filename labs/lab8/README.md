## Створення тестових даних

Git **не зберігає порожні каталоги**, тому після клонування репозиторію їх треба створити вручну.

Linux / macOS / Git Bash / Windows:

```bash
mkdir -p test_sandbox/nested_dir
echo "2026-08-30 System started successfully" > test_sandbox/system.log
echo "2026-08-30 Warning: low disk space on /dev/sda1" >> test_sandbox/system.log
echo "ELF_DUMMY_BINARY_DATA_PAYLOAD_STREAM_BUFFER" > test_sandbox/firmware.bin
echo '{"status": "active", "port": 8080}' > test_sandbox/config.json
echo "2026-08-30 Application memory dump core" > test_sandbox/nested_dir/app_dump.log

# порожні каталоги для перевірки варіанта 2
mkdir -p test_sandbox/empty_dir test_sandbox/nested_dir/empty_sub test_sandbox/empty_tree/level1
```

PowerShell (лише порожні каталоги; файли вже є в репозиторії):

```powershell
mkdir test_sandbox\empty_dir, test_sandbox\nested_dir\empty_sub, test_sandbox\empty_tree\level1
```

## Запуск

```bash
conda activate ce_lab_env
python cli_main.py --help                             # довідка
python cli_main.py --path ./test_sandbox --dry-run    # лише показати, що буде видалено
python cli_main.py --path ./test_sandbox              # реальне видалення
```

Без прапорця `--dry-run` порожні каталоги **видаляються**. Спершу завжди запускайте з `--dry-run`. Після реального видалення створіть порожні каталоги заново командами вище.

## Коди завершення

| Код | Значення |
|---|---|
| 0 | успіх |
| 1 | помилка синтаксису аргументів |
| 2 | некоректний шлях або заборонене видалення в кореневому чи домашньому каталозі |
| 3 | критичний збій |
| 4 | частину директорій не вдалося видалити |

## Що реалізовано

- ручний розбір `sys.argv` без сторонніх бібліотек, `--help`/`-h`, перевірка відсутнього значення `--path`, `sys.exit(code)`;
- обхід лише через `pathlib.Path`: `rglob`, `is_dir`, `is_symlink`, `iterdir`, `stat`, `rmdir`;
- `find_empty_directories`: один прохід `rglob("*")`, каталоги впорядковуються за глибиною від найглибших, каталог порожній, якщо кожен його елемент уже визнаний порожнім каталогом; для кожного збираються час модифікації та права доступу `oct(st_mode & 0o777)`;
- `remove_empty_directories`: режим імітації (`--dry-run`) або `Path.rmdir()`, який не видаляє непорожні каталоги;
- безпека: базовий каталог не видаляється, недоступні каталоги вважаються непорожніми, символьні посилання не розкриваються, реальне видалення в `/` і домашньому каталозі заборонено;
- `fs_toolkit/__init__.py` із `__all__`: приватні функції з префіксом `_` не експортуються.

## Результат

У пісочниці знайдено 4 порожні каталоги (3 повністю порожні і `empty_tree` із порожнім підкаталогом) із 6 проскановано. Каталог `nested_dir` залишається, бо містить `app_dump.log`. Повторний запуск після видалення знаходить 0 порожніх каталогів.
